Evaluation Programme · Platform Review

Choosing Our Eval Platform

A comparison of three platforms for running evaluation on live production traffic and surfacing the results in the product: Confident AI, LangSmith and Langfuse.

21 August 2026 Pricing and feature details verified against vendor pages on this date
1 · Scope

What this document decides

  • Evaluation completed so far is offline: a generated test set of questions and multi-turn conversations, run against the chatbots and scored.
  • The next stage is online evaluation: scoring a sample of live customer conversations on a continuous basis.
  • Online evaluation requires a platform that traces the running application and stores the scores.
  • This document compares the three candidates and recommends one.

2 · Requirements

Criteria used for the comparison

  1. Online evaluation on production traffic, with sampling to control cost.
  2. Scores readable through an API, so the admin view and the customer evaluation tab can be rendered inside our own product.
  3. No cap on the number of chatbots or projects.
  4. Pricing that does not scale per user seat.
  5. Self-hosting available, in case a customer requires conversation data to stay on our infrastructure.
  6. A supported TypeScript SDK, since the application is a TypeScript Next.js codebase.
3 · Platform

Confident AI

Hosted platform built by the makers of DeepEval, the framework used for our offline suite.

Features

  • Tracing of each execution as traces, spans and threads.
  • Online evaluation: “continuously evaluate production traffic using 50+ metrics”, run in real time as traces are ingested or retrospectively.
  • Sampling controls, monitors and alerting on quality, latency and cost.
  • Datasets, prompt versioning, human annotation, CI/CD integration.
  • Instrumentation via an @observe decorator, framework integrations, or OpenTelemetry. Python and TypeScript supported.
  • REST API: “Every part of Confident AI is exposed as an API”.
  • No self-hosted deployment option.

  • Online evaluation is not available on the Free plan. Entry price is $200/month.

  • No self-hosting, so conversation data cannot be kept on our infrastructure.
  • API access and TypeScript support: both available.
4 · Platform

LangSmith

LangChain’s hosted observability and evaluation platform. Proprietary; the client SDKs are open source, the platform is not.

Features

  • Tracing, datasets, experiments, prompt management and online evaluators on production traces.
  • Closest integration with LangChain and LangGraph; tracing for those frameworks enables via a single environment variable.
  • Python and JS/TS SDKs. OpenTelemetry ingestion supported as a secondary path.
  • Self-hosted and hybrid deployment listed on the Enterprise plan only.

5 · Platform

Langfuse

Open-source observability and evaluation platform, MIT licensed. All product features were moved to MIT in June 2025; SCIM, audit logs, project-level access control and UI customisation remain commercial. Acquired by ClickHouse in January 2026, licence unchanged.

Features

  • Tracing — “all LLM and non-LLM calls, including retrieval, embedding, API calls”, with sessions, user tracking and agent-graph visualisation.
  • Evaluation — LLM-as-a-judge, code evaluators, user feedback, manual labelling, custom pipelines. Open source since v3.65.0.
  • Code evaluators — TypeScript or Python evaluate functions written in the UI, shipped May 2026. Deterministic checks run without a judge model call.
  • Sampling — “configure sampling percentage (e.g. 5%) to manage evaluation costs and throughput”, applied deterministically per observation.
  • Prompt management — versioning and label-based deployment.
  • Datasets and annotation queues — existing offline goldens and human review.
  • Public API — scores, observations, metrics and dashboard endpoints, typed in the JS/TS SDK.
  • TypeScript SDK v5 — OpenTelemetry-based. Documented Next.js path: “register the LangfuseSpanProcessor via registerOTel from @vercel/otel as long as you are on @vercel/otel v2 or later”.
  • Self-hosting — free, with all core platform features and APIs.

Self-hosting requirement

Self-hosted Langfuse carries no licence cost but requires PostgreSQL, ClickHouse, Redis and object storage to be operated by us. Because the licence is MIT and the API is identical between cloud and self-hosted, moving from cloud to self-hosted later does not require application changes.

7 · Recommendation

Langfuse, on the $29/month cloud plan

  • Lowest entry price for online evaluation of the three.
  • No per-seat charge and no project cap, so cost does not move with team size or chatbot count.
  • Self-hosting available at no licence cost if a customer requires data residency, with no application changes needed to move.
  • MIT licence for the full platform.
  • TypeScript SDK is OpenTelemetry-native with a documented Next.js integration path.
  • Scores are readable through the public API, so the admin view and customer evaluation tab are built inside our own product.

Judge-model tokens are charged by the model provider on top of the platform cost, on whichever platform is chosen. Our completed offline run — 30 single-turn questions and 10 multi-turn conversations, scored on a small judge model — cost under $2 in total. Sampling percentage and the use of code evaluators, which require no model call, both reduce this.

8 · Separate requirement

Prompt-injection measure

  • DeepEval’s core metric set does not include a prompt-injection metric.
  • None of the three platforms above provides one as a standard metric.
  • Injection testing is adversarial — attacks are constructed and checked for success — so it runs as a pre-release check rather than as a sample of live traffic.
  • promptfoo’s red-team module generates adversarial inputs across prompt injection, jailbreaks, PII leakage and hijacking, and reports which attacks succeeded. Open source.
  • DeepTeam, from the DeepEval authors, is the alternative and shares the vocabulary of our existing suite.
9 · Next steps

Proposed sequence

  1. Instrument the application. Add the Langfuse TypeScript SDK to the chat path so conversations, retrieval steps and tool calls are traced.
  2. Enable sampled online evaluation. Configure the judge model and code evaluators, start at a low sampling percentage, and compare results against the existing offline scores.
  3. Build the admin view. Read scores through the Metrics API into an internal page covering all chatbots.
  4. Build the customer evaluation tab. The same data filtered to a single account.
  5. Add the prompt-injection check. promptfoo red-team run wired into the release process.

Each step is usable on its own, so the sequence can be paused or re-ordered without discarding work.
